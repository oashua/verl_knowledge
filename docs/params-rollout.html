Rollout 参数

参数命名空间 actor_rollout_ref.rollout.*，默认值取自 verl/trainer/config/rollout/rollout.yaml（2025-10 main 分支）。 并行与显存相关参数的原理见并行篇与显存篇，本页按功能分组速查。

1. 引擎与模式选择

参数默认说明
rollout.name必填推理后端：vllm / sglang / trtllm / hf。vLLM 与 SGLang 是主流选择，按基础设施实测挑选
rollout.modeasyncsync=LLM 批式接口，async=AsyncLLM。多轮/agent 场景必须 async
rollout.dtypebfloat16推理权重 dtype，与训练侧对齐
rollout.load_formatdummy权重加载方式：dummy（随机初始化，等第一次同步）/ hf / megatron / safetensors（超大模型，配 data.use_shm=True）
rollout.skip_tokenizer_initTruetoken-in-token-out，跳过引擎内 tokenizer 初始化
rollout.seed42vLLM 采样种子
rollout.engine_kwargs.{vllm,sglang,trtllm}.*{}透传引擎原始 CLI 参数的逃生口，如 +...engine_kwargs.vllm.disable_log_stats=True

2. 采样参数

参数默认说明
rollout.temperature1.0RL 探索默认 1.0；调低会缩小策略分布，训练信号变弱
rollout.top_p / top_k1.0 / -1官方建议训练 rollout 保持全分布（top_p=1、top_k=-1）；top_k 语义：-1=vLLM 不限，0=HF 不限
rollout.n1每 prompt 采样数 = GRPO 组大小 G。GRPO 典型 64，DAPO 16。同时等于 critic/ref/log-prob 的样本放大倍数
rollout.do_sampleTrueHF rollout 用；False 为贪心
rollout.ignore_eosFalseTrue = 生成到 response_length 上限（测量极限吞吐用）
rollout.over_sample_rate0过采样提前终止：完成 (1−rate) 比例请求即终止其余（DAPO filter_groups 配合）
rollout.val_kwargs.*temp=0验证期独立采样参数。小测试集（AIME24）建议 temperature>0 + n=64 降方差，起步 temp=1.0, top_p=0.7, n=1
验证也要采样：温度设 0 时思维链模型容易重复循环——官方建议验证 temperature > 0。

3. 生成长度

参数默认说明
rollout.prompt_length= data.max_prompt_length输入上限；数据侧过长报错或按 data.truncation 截断
rollout.response_length= data.max_response_length生成上限。日志中 clip_ratio > 0.1 通常说明截断过多，应加长或清数据
rollout.max_model_lennull引擎最大序列长度（prompt+response）；null 自动。加大直接增加 KV cache 压力

4. 显存相关

参数默认说明
rollout.gpu_memory_utilization0.5引擎总预算。vLLM≥0.7 按总显存比例，SGLang 按空闲显存中静态部分比例；offload 全开后可 0.8–0.9
rollout.standalone_gpu_memory_utilization同上separate_async 独立 rollout 池的专用值
rollout.enforce_eagerFalseTrue 关 CUDA graph 省显存（慢 ~10%+）
rollout.cudagraph_capture_sizesnull只捕获指定 batch 尺寸的 graph，如 [1,2,4,8,16,32]
rollout.free_cache_engineTrue生成结束释放 KV cache（hybrid 模式必开）
rollout.multi_stage_wake_upFalseSGLang：多阶段唤醒，降低训练→推理切换峰值
rollout.layered_summonFalse分层 summon 权重，防同步 OOM，更慢

5. 吞吐相关

参数默认说明
rollout.tensor_model_parallel_size2越小 replica 越多吞吐越高（详见并行篇 §5）
rollout.data_parallel_size / expert_parallel_size / pipeline_model_parallel_size1推理 DP/EP/PP；vLLM EP 须满足 EP=TP×DP
rollout.max_num_seqs256并发请求上限；KV 利用率低时调大
rollout.max_num_batched_tokens8192每 batch token 上限；经验 max(8192, prompt+response, max_model_len)
rollout.enable_chunked_prefillTruechunked prefill；开时需协调 max_num_batched_tokens / max_model_len
rollout.enable_prefix_cachingTrueprefix KV 复用；GRPO n>1 与多轮场景收益大
rollout.scheduling_policyfcfs调度策略（vLLM）
rollout.disable_log_statsTrue调优期改 False，看 KV 利用率与并发数
rollout.ray_actor_max_concurrency1024rollout server actor 并发上限，需高于在途请求数峰值，否则 wake_up/权重同步被饿死

6. log-prob 计算参数

rollout 引擎只负责生成；π_old 的 log-prob 由训练侧模型前向计算，参数也挂在 rollout 节点下：

参数默认说明
rollout.log_prob_micro_batch_size_per_gpunull固定 batch 路径的每卡批大小（纯前向，可设 actor 的 2 倍）
rollout.log_prob_use_dynamic_bsz= actor.use_dynamic_bsz动态打包（推荐 True）
rollout.log_prob_max_token_len_per_gpu= actor.ppo_max_token_len_per_gpu (16384)每卡 token 预算；须 ≥ n×max_prompt_length+max_response_length 的整倍数，防止截断
rollout.calculate_log_probsTrue记录 rollout 自身 log-prob（truncated importance sampling 等需要时开）
rollout.logprobs_modeprocessed_logprobslogprobs 输出模式
rollout.topk_log_probs0每 token top-k log-probs（rollout_correction score centering 用，vLLM 单轮）

7. 多轮工具调用（multi_turn）

actor_rollout_ref.rollout.name=sglang        # 多轮建议 SGLang
actor_rollout_ref.rollout.multi_turn.enable=True
参数默认说明
multi_turn.tool_config_pathnull有状态工具 YAML（每轨迹状态、create/release 生命周期、自定义 reward）
multi_turn.function_tool_pathnull@function_tool 装饰的无状态工具 Python 文件；与 tool_config_path 可共存（重名报错）
multi_turn.max_assistant_turns / max_user_turnsnull (max_length//3)轮数上限
multi_turn.max_parallel_calls1单轮最多并行工具调用
multi_turn.max_tool_response_length256工具返回 token 上限；超出按 tool_response_truncate_side（默认 middle）截
multi_turn.formathermes工具调用协议格式（hermes / llama3_json …）
multi_turn.use_inference_chat_templateFalseFalse=用记录的 token ids 训练（含完整输出，训练/推理一致但 prompt 更长）；True=用默认 chat template（贴近生产）
multi_turn.tokenization_sanity_check_modestrict逐轮 vs 整体分词一致性检查；QwQ/Qwen3 等已知差异模型可设 ignore_strippable 或 disable

8. Agent Loop（实验性）

基于 AgentLoop worker 的异步 agent rollout，适合复杂工具编排：

  • rollout.agent.num_workers（默认 8）— agent loop worker 数
  • rollout.agent.default_agent_loop（默认 single_turn_agent）— 未在数据集标 agent_name 时使用
  • rollout.agent.agent_loop_config_path — hydra 实例化配置，注册自定义 loop（react_agent 等）
  • rollout.agent.custom_async_server.* — 自定义异步推理服务（如 AsyncvLLMServer）
  • rollout.trace.* — 轨迹追踪（mlflow/weave/trackio 后端、token2text、每 worker 每步采样条数）

9. 权重同步（checkpoint engine）

参数默认说明
rollout.checkpoint_engine.backendnaive权重广播后端：naive / nccl / nixl / hccl；大模型多机时 nccl/nixl 显著更快
rollout.checkpoint_engine.update_weights_bucket_megabytes2048单次权重更新 payload 上限（SGLang）；更大吞吐更高但显存开销增加。TP≥8 时建议同时设 RAY_EXPERIMENTAL_NOSET_CUDA_VISIBLE_DEVICES=1 + 手动 CUDA_VISIBLE_DEVICES

10. 进阶：PD 分离、KV offload、量化、MTP

10.1 PD 分离（SGLang）

长 prompt 场景把 prefill 与 decode 拆到不同 replica：

rollout.disaggregation.enabled=True
rollout.disaggregation.prefill_replicas=1     # 每 replica 占 TP 张卡
rollout.disaggregation.decode_replicas=1
rollout.disaggregation.decode_tensor_model_parallel_size=null  # null=同 TP
rollout.disaggregation.transfer_backend=nixl   # nixl | mooncake | ascend | mori

10.2 KV cache offload（Mooncake，vLLM）

把 prefix KV 块 offload 到共享 Mooncake store：长共享前缀（系统提示、工具历史、GRPO 的 n 采样） 跨请求/跨 replica 去重，并降低迁移负载时的 re-prefill 成本。需 vLLM ≥ 0.22（旧版本权重更新后可能残留陈旧 KV； verl 每次权重更新会强制清空本地与 Mooncake 缓存）： 

+actor_rollout_ref.rollout.engine_kwargs.vllm.kv_transfer_config.kv_connector=MooncakeStoreConnector
+actor_rollout_ref.rollout.engine_kwargs.vllm.kv_transfer_config.kv_role=kv_both
+actor_rollout_ref.rollout.engine_kwargs.vllm.kv_transfer_config.kv_connector_extra_config.mooncake_config_path=/path/to/mooncake_config.json

10.3 低精度 rollout 与 MTP

  • rollout.quantization.{linear,moe}（如 FP8_BLOCK）— vLLM/SGLang + Megatron：引擎以量化配置启动，训练侧每次同步前量化权重
  • rollout.mtp — multi-token prediction，复用模型配置
  • rollout.enable_rollout_routing_replay / moe_load_balance_metrics_interval — MoE 路由记录回放与负载指标
