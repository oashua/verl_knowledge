1. 算法选择：advantage estimator 与 KL

参数默认说明
algorithm.adv_estimatorgae优势估计器：gae（PPO，需 critic）/ grpo（组内归一化）/ reinforce_plus_plus 等。选 gae 以外的值则 critic 默认不创建
algorithm.gamma1.0折扣因子；LLM RL 常用 1.0（稀疏末位奖励 + 无环境动态）
algorithm.lam1.0GAE 偏差-方差权衡；同样常用 1.0
algorithm.norm_adv_by_std_in_grpoTrueGRPO 组内优势是否除以 std。Dr.GRPO 建议关闭（除 std 会给小方差组放大数据噪声）
algorithm.use_kl_in_rewardFalseKL 写进 reward（PPO 用）；GRPO/DAPO 用 loss 侧 KL 或完全不用
algorithm.kl_penaltyklKL 估计方式：kl / abs / mse(k2) / low_var_kl(k3) / full
algorithm.kl_ctrl.typefixedfixed：固定系数 kl_coef；adaptive：按 target_kl 自适应（horizon 平滑窗口）
algorithm.kl_ctrl.kl_coef0.001KL 系数起点；过大抑制探索、过小易 reward hacking
algorithm.filter_groups.*enable=FalseDAPO 组过滤（全对/全错组丢弃）：metric 选奖励字段，max_num_gen_batches / max_inflight_gen_batches 控制补采
ref 模型何时存在：use_kl_in_reward=True 或 actor.use_kl_loss=True 时才创建 reference worker （DAPO 两者皆 False 时 ref 完全不加载，省一份静态显存）。

2. 数据流参数

参数默认说明
data.train_files / val_filesgsm8k parquetparquet 格式（可列表）；全量读入内存（<100GB）
data.train_batch_size1024每次迭代的 prompt 数（全局量）；每步实际样本数 = × rollout.n
data.gen_batch_sizenull（=train）每次从 dataloader 取的 prompt 数；异步模式可调大攒批
data.max_prompt_length / max_response_length512 / 512长度上限；日志 clip_ratio>0.1 说明 response 截断过多
data.truncationerror超长 prompt 处理：error / left / right / middle。常规跑 left，严格验证用 error
data.filter_overlong_promptsFalse预过滤超长样本（大数据集配 filter_overlong_prompts_workers 多进程加速）
data.prompt_key / reward_fn_keyprompt / data_source数据列名；data_source 决定用哪个 reward 函数
data.val_batch_sizenull验证 batch（null 自动）
data.shuffle / seedTrue / nulldataloader 打乱与种子
data.use_shmFalse共享内存加载数据（safetensors 大模型权重同步时用）

3. Actor 更新参数

3.1 批次结构

train_batch_size × n  ─(PPO epochs)→  ppo_mini_batch_size  ─(累积)→  micro_batch（动态 token 预算）
参数默认说明
actor.ppo_mini_batch_size256一次优化 step 的样本数（全局）；按常规 DL 调法
actor.ppo_micro_batch_size_per_gpunull每卡前反向批大小；尽量调大至 mini batch 归一化值（性能细节见性能篇 §4）
actor.ppo_max_token_len_per_gpu16384动态 batch 的每卡 token 预算
actor.ppo_epochs1数据重用次数；>1 更 off-policy，GRPO/DAPO 通常保持 1
actor.shuffle / data_loader_seedFalse / 42epoch 间打乱与切分种子

3.2 策略 loss 与裁剪

参数默认说明
actor.clip_ratio0.2PPO 对称裁剪 ε
actor.clip_ratio_low / clip_ratio_high0.2 / 0.2非对称裁剪（DAPO clip-higher）：low=0.2、high=0.28，放宽低概率 token 上探
actor.clip_ratio_c3.0dual-clip PPO 的 C：advantage<0 且 ratio>C 时额外截断，防早期崩坏
actor.loss_agg_modetoken-meanloss 聚合：token-mean（Dr.GRPO/DAPO 推荐）/ seq-mean-token-mean（原版 GRPO）/ seq-mean-token-sum 等；配合 loss_scale_factor（null=按 response_length）
actor.policy_loss.loss_modevanilla扩展 loss：clip-cov / kl-cov（GPG，arXiv:2505.22617）/ dro
actor.entropy_coeff0entropy 正则；>0 时注意显存（见显存篇 §4.3）
actor.tau_pos / tau_neg1.0 / 1.05SAPO 平滑函数参数（Qwen3-30B-A3B 论文默认）
actor.use_kl_lossFalseKL 作为 loss 项（GRPO True / PPO False / DAPO False）
actor.kl_loss_coef0.001KL loss 权重，起点 0.001
actor.kl_loss_typelow_var_klKL 估计（k3 低方差推荐）
actor.grad_clip1.0梯度范数裁剪（FSDP 路径）

4. Critic 参数

命名空间 critic.*。仅在 adv_estimator=gae 时默认启用（critic.enable 可强制）。

参数默认说明
critic.model.path—critic 初始权重（常与 actor 同底座，另训 value head）
critic.ppo_mini_batch_size / ppo_epochs / loss_agg_mode继承 actor默认与 actor 联动，可单独覆盖
critic.ppo_max_token_len_per_gpu32768已是 actor 默认（16384）的 2 倍——critic 输出头是标量，可更大
critic.cliprange_value0.5value function 裁剪范围
critic.optim.lr1e-5critic 学习率通常比 actor（1e-6）大一个量级
trainer.critic_warmup0训练前先单独热身 critic 的迭代数
critic.strategy必填fsdp / fsdp2 / megatron（可独立于 actor 选择）

5. Optimizer 与 LR scheduler

命名空间 actor.optim.* / critic.optim.*（以及 FSDP 专属扩展在 *.fsdp_config.optim 层，Megatron 专属在 *.megatron.optim 层）。

参数默认（actor）说明
optim.lr1e-6RL 微调常用 1e-6~1e-5；critic 默认 1e-5
optim.weight_decay0.01官方实践常用 0.1
optim.lr_warmup_steps-1优先于 ratio；None/负值回退到 lr_warmup_steps_ratio。常见 10 步或 ratio 0.0~0.1
optim.clip_grad1.0梯度裁剪，常用 1
optim.betas[0.9, 0.999]Adam β（FSDP 路径）
optim.lr_scheduler_typeconstantFSDP：constant / cosine（配 min_lr_ratio、num_cycles）
fsdp.optimizer / optimizer_implAdamW / torch.optim可换 bitsandbytes AdamW8bit、torchao _AdamW（bf16 随机舍入）等
megatron.optim.optimizeradamadam / sgd / muon（走 MCore emerging_optimizers，TP 感知 Muon，有十余个 muon_* 子项）
megatron.optim.lr_decay_styleconstantconstant / linear / cosine / inverse_square_root；另有 WSD 风格 lr_wsd_decay_style + lr_wsd_decay_steps
+megatron.optim.use_precision_aware_optimizerFalsebf16 优化器状态（main_grads/exp_avg 可设 bf16），显著省优化器显存，需 TE FusedAdam
+fsdp.optim.override_optimizer_config.optimizer_offload_fraction—部分优化器计算放 CPU；DeepSeek 级模型官方建议设 1，配套 overlap_cpu_optimizer_d2h_h2d / use_precision_aware_optimizer

6. Trainer 杂项与 checkpoint

参数默认说明
trainer.total_epochs / total_training_steps30 / nullepoch 与步数二选一，steps 优先
trainer.test_freq / val_before_train-1 / True验证频率（迭代数）/ 训练前基线验证
trainer.save_freq-1checkpoint 保存间隔；default_local_dir 默认 checkpoints/<project>/<exp>
trainer.max_actor_ckpt_to_keep / max_critic_ckpt_to_keepnull滚动保留数量
trainer.resume_modeautoauto / disable / resume_path（配 resume_from_path）
actor.checkpoint.save_contents[model, optimizer, extra]可加 hf_model 导出 HF 格式（分片）；load_contents 可只载部分
actor.checkpoint.async_saveFalse异步保存（目前仅 Megatron）
trainer.balance_batchTrue跨 DP worker 按 token 均衡批次（长尾分布下防 straggler）
trainer.logger / project_name / experiment_name[console, wandb] / verl_examples / gsm8k实验追踪
trainer.log_val_generations0记录验证生成样本条数（建议 10 起步，便于观察退化）

7. 算法配方速查：PPO / GRPO / DAPO / REINFORCE++

按官方 best_practices（DAPO = KL 增强版视角）整理的关键差异：

参数PPOGRPODAPOREINFORCE++
algorithm.adv_estimatorgaegrpogrporeinforce_plus_plus
critic需要无无无
algorithm.use_kl_in_rewardTrueFalseFalseFalse
actor.use_kl_lossFalseTrue（kl_loss_coef≈0.001）False视实现
ref 模型需要需要不需要不需要
rollout.n（组大小 G）1典型 64典型 16组内基线>1 可选
actor.clip_ratio_low/high0.2/0.20.2/0.20.2/0.280.2/0.2
actor.loss_agg_modetoken-meanseq-mean-token-mean（原版）/ token-mean（Dr.GRPO）token-meantoken-mean
reward_model.reward_managernaivenaivedapo（组过滤）naive
algorithm.filter_groups.enableFalseFalseTrueFalse

现成变体 trainer（dppo / gspo / gmpo / remax / rloo / gpg …）在 examples/<name>_trainer/， 多数只需换 adv_estimator + 少量开关，不建议手搓全部超参。
