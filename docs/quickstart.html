1. 安装

1.1 uv 工作流（官方推荐）

克隆仓库后无需手动安装，uv run 按仓库锁定的 uv.lock 构建 .venv：

git clone https://github.com/volcengine/verl.git && cd verl
UV_RUN="uv run --frozen --all-packages --extra vllm --extra fsdp"
$UV_RUN python3 --version   # 首次运行自动建环境

extras 选择规则：

  • 推理引擎二选一：--extra vllm 或 --extra sglang（不可同时）； vLLM 需 0.18.0+，旧版已不可用
  • 训练后端：--extra fsdp（PyTorch FSDP）/ --extra megatron，可只选其一
  • 组合示例：--extra vllm --extra megatron（vLLM 推理 + Megatron 训练）

1.2 Docker

DOCKER_BUILDKIT=1 docker build -f docker/Dockerfile.uv.cu130 -t verl:uv-cu130 .
docker run --rm -it --gpus all verl:uv-cu130 bash
# 容器内：
uv run --frozen --all-packages --extra sglang --extra megatron python3 -m verl.trainer.main_ppo ...

国产/异构硬件另有独立 Dockerfile：docker/ascend/（昇腾）、docker/rocm/（AMD）等。

1.3 硬件门槛

官方 quickstart 要求单卡 ≥ 24GB HBM（Qwen2.5-0.5B PPO）。7B 级 FSDP 起步建议单机 8×80G。

2. 数据准备

verl 统一用 parquet（全量载入内存，建议 <100GB）。GSM8K 一键转换：

$UV_RUN python3 examples/data_preprocess/gsm8k.py --local_save_dir ~/data/gsm8k
# 产出 ~/data/gsm8k/train.parquet 与 test.parquet

parquet 必需字段（自定义数据集按此对齐）：

字段作用
prompt输入（data.prompt_key 可改列名）
data_source路由到哪个 reward 函数（data.reward_fn_key）
reward_model奖励函数的元数据（如 ground truth 答案）

GSM8K 用规则奖励：从模型输出里正则抽取 #### 后的最终答案，对了 +1，错了 0。其他数据集的转换脚本都在 examples/data_preprocess/。

3. 模型准备

quickstart 用 Qwen/Qwen2.5-0.5B-Instruct。提前拉取（网络受限可设 VERL_USE_MODELSCOPE=True 改从 ModelScope 下载）：

python3 -c "import transformers; transformers.pipeline('text-generation', model='Qwen/Qwen2.5-0.5B-Instruct')"

4. 第一次训练（两种方式）

4.1 裸 hydra 命令（理解参数用）

官方 quickstart 的 0.5B PPO 最小命令（单卡 24G+ 可跑）：

PYTHONUNBUFFERED=1 python3 -m verl.trainer.main_ppo \
  data.train_files=$HOME/data/gsm8k/train.parquet \
  data.val_files=$HOME/data/gsm8k/test.parquet \
  data.train_batch_size=256 \
  data.max_prompt_length=512 data.max_response_length=512 \
  actor_rollout_ref.model.path=Qwen/Qwen2.5-0.5B-Instruct \
  actor_rollout_ref.actor.optim.lr=1e-6 \
  actor_rollout_ref.actor.ppo_mini_batch_size=64 \
  actor_rollout_ref.actor.ppo_micro_batch_size_per_gpu=4 \
  actor_rollout_ref.rollout.name=vllm \
  actor_rollout_ref.rollout.log_prob_micro_batch_size_per_gpu=8 \
  actor_rollout_ref.rollout.tensor_model_parallel_size=1 \
  actor_rollout_ref.rollout.gpu_memory_utilization=0.4 \
  actor_rollout_ref.ref.log_prob_micro_batch_size_per_gpu=4 \
  critic.optim.lr=1e-5 \
  critic.model.path=Qwen/Qwen2.5-0.5B-Instruct \
  critic.ppo_micro_batch_size_per_gpu=4 \
  algorithm.kl_ctrl.kl_coef=0.001

uv 工作流下前面加 $UV_RUN，并加 ray_kwargs.ray_init.runtime_env.py_executable="$UV_RUN" 让 Ray worker 也用同一环境（examples/ 脚本已自动处理）。

4.2 官方脚本（实际使用推荐）

环境变量覆盖、开箱即调好批次与显存：

# GRPO + Qwen3-4B，单机 8 卡
bash examples/grpo_trainer/run_qwen3_4b_fsdp.sh

# 换推理后端 / 换卡数 / 换模型
INFER_BACKEND=sglang bash examples/ppo_trainer/run_qwen3_8b_fsdp.sh
NNODES=2 bash examples/grpo_trainer/run_qwen2_5_32b_fsdp.sh

各量级脚本的完整参数解读见Recipes 篇； 参数含义查训练核心参数与Rollout 参数。

5. 判断训练是否正常

盯 console / wandb 里的这几组指标（默认 logger=["console","wandb"]）：

指标正常形态异常信号
critic/score/mean（或 val score）平稳上升后平台长期不动（奖励没信号）或骤降后不恢复（崩了）
response_length/mean任务相关（数学类常缓慢变长）暴涨到 max_response_length 上限（截断环，看 clip_ratio 确认）
rollout clip_ratio（截断比例）< 0.1> 0.1 说明 response_length 不够，加长或清数据
actor clip_ratio/mean（PPO 裁剪）低个位数百分比接近上限 mini-batch 全被裁（lr 过大或 ppo_epochs 过多）
kl（KL with ref）缓慢增长后稳住爆涨（策略漂移过快，加 kl_coef）
entropy先降后稳快速归零（探索死亡，奖励坍缩到单一答案）
timing 分解gen / update 各占合理比例某阶段占 90%+ → 去性能篇 §1定位

6. 短试运行技巧

正式跑之前永远先做一次廉价验证：

# 只跑 10 步：验证配置能启动、显存峰值、每步耗时
trainer.total_training_steps=10

# 只验证不训练（模型/数据/reward 链路通了没）
trainer.val_only=True  trainer.val_before_train=True

# 排查 rollout：打开引擎统计看 KV 利用率
actor_rollout_ref.rollout.disable_log_stats=False

OOM 了去显存篇的降级阶梯，按代价从小到大逐项试，不要一次全开。
