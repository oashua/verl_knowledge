1. 总览：GPU 预算与角色划分

verl 基于 HybridFlow 架构：一个单控制器（Ray driver）调度多个 worker group， 每个 group 承担一个角色（actor / rollout / reference / critic / reward model）。 总 GPU 数由两个参数决定： 

world_size = trainer.nnodes × trainer.n_gpus_per_node
  • trainer.nnodes — 训练节点数（默认 1）
  • trainer.n_gpus_per_node — 每节点 GPU 数（默认 8）

默认 actor_rollout_ref.hybrid_engine=true：actor（训练）与 rollout（推理引擎）共置在 同一组 GPU 上，通过 sleep/wake 在「生成」和「更新」两个阶段间切换显存占用。ref、critic、reward 也各自拥有覆盖全部 GPU 的 worker group。因此同一时刻每个角色都独占全部 world_size 张卡， 并行度参数描述的是「这个角色内部的切分方式」，而不是角色之间的分配。

异步模式：trainer.v1.trainer_mode 可选 sync（默认）/ colocate_async / separate_async。separate_async 下 rollout 使用 独立 GPU 池（actor_rollout_ref.rollout.nnodes / rollout.n_gpus_per_node），此时训练与推理的 GPU 预算才真正分开。

2. 训练后端选择：FSDP 还是 Megatron

verl 通过 model_engine 选择训练后端，决定后续所有引擎参数的命名空间：

model_engine引擎参数命名空间适用场景
dp（默认，PyTorch FSDP） actor_rollout_ref.actor.fsdp_config.* ≤ 70B 常用；上手简单，FSDP2 + torch.compile 吞吐不差；MoE 大模型支持有限
megatron actor_rollout_ref.actor.megatron.* 超大模型 / 大规模集群；TP+PP+EP 组合、分布式优化器、MoE（DeepEP 等）
torchtitan / veomni *.torchtitan.* / *.veomni.* 较新的后端，覆盖面较小，本文不展开

注意在 verl 新版配置里不再直接写 actor_rollout_ref.actor.strategy，而是 hydra 启动参数 model_engine=megatron（等价于 actor.strategy=megatron + 加载 megatron 引擎配置组）。

3. FSDP 后端：fsdp_size 与 Ulysses 序列并行

3.1 fsdp_size：分片粒度

FSDP 后端没有 TP/PP 概念，模型权重/梯度/优化器状态沿 DP 维度分片。 fsdp_config.fsdp_size 决定一个分片组包含多少张卡（源码 verl/workers/engine/fsdp/utils.py: create_device_mesh）：

fsdp_sizedevice mesh语义通信范围
-1（默认）或 ≥ world_size (world,) 全分片（ZeRO-3）：参数在全部卡间分片，每卡持有 1/N all-gather / reduce-scatter 全局
0 < fsdp_size < world (world//fsdp_size, fsdp_size) Hybrid Shard（ZeRO-2+）：fsdp_size 张卡组成一个分片组，组间纯数据并行 通信限制在分片组内（通常对齐单机 8 卡）

于是 FSDP 后端的有效数据并行度为：

DP = world_size / fsdp_size        （fsdp_size=-1 时即 world_size）
DP_effective = DP / ulysses_sp     （再除以序列并行度）
怎么选：默认全分片最省显存；单机内带宽好、跨机带宽差时，把 fsdp_size 设为 每节点 GPU 数（如 8、16），可把通信限制在机内并减少跨机 all-gather，往往更快。

3.2 ulysses_sequence_parallel_size：序列并行（长序列）

序列长度 > 32k 时，即使 micro-batch=1，单条序列的激活与 logits 也可能 OOM。FSDP 后端用 Ulysses 序列并行把一条序列沿 sequence 维切到 sp 张卡上：

  • fsdp_config.ulysses_sequence_parallel_size = sp > 1
  • mesh 变为 (dp, sp)；head 维度需能被 sp 整除（attention head 在 sp 间切分）
  • 要求 model.use_remove_padding=True（THD 打包路径），否则报错
  • 开启后需要相应调小 *max_token_len_per_gpu 等每卡 token 预算（见性能篇）

3.3 其他 FSDP 引擎参数

参数默认说明
fsdp_config.strategyfsdp可选 fsdp2（推荐，平均省 ~7% 显存、+1.5% 吞吐）、fsdp_turbo
fsdp_config.param_offloadfalse参数 offload 到 CPU，换速度省显存
fsdp_config.optimizer_offloadfalse优化器状态 offload 到 CPU
fsdp_config.reshard_after_forwardtrueFSDP1 中设 false 等价 SHARD_GRAD_OP（前向后不重分片，省 all-gather 但更费显存）
fsdp_config.forward_prefetchfalseFSDP1 预取下一次前向的 all-gather，通信/计算重叠提速
fsdp_config.use_no_sync_for_gradient_accumulationfalse梯度累积时只在最后一个 micro-batch 同步梯度（M 次 → 1 次通信），峰值显存上升
fsdp_config.dtypebfloat16混合精度参数 dtype

4. Megatron 后端：TP / PP / CP / EP / ETP

Megatron 后端参数位于 actor_rollout_ref.actor.megatron.*，满足基本约束： 

world_size = TP × PP × CP × DP          （稠密模型）
EP 从 DP 维度再切分（MoE）：world_size = TP × PP × CP × EP × DP_dense
  其中 expert 权重按 EP 分片，dense 权重按 DP 分片

4.1 五种并行各自切什么

参数切分对象作用与代价
tensor_model_parallel_size (TP) 层内权重矩阵 每参数显存 ÷ TP；引入每层 all-reduce，跨机 TP 通信代价大，尽量 ≤ 单机 GPU 数（NVLink 域）
pipeline_model_parallel_size (PP) 按 transformer 层切到不同 stage 每参数显存 ÷ PP；通信量小（只传激活），但有 bubble；用 micro-batch 数与 virtual pipeline 缓解
context_parallel_size (CP) 序列维度 长序列专用：激活、logits 随序列长度 ÷ CP；attention 计算需跨 CP 通信。可配 dynamic_context_parallel=True 按实际长度动态调度（需设 max_seqlen_per_dp_cp_rank）
expert_model_parallel_size (EP) MoE 专家 专家权重 ÷ EP；适合 MoE 模型（如 64×A100 跑 DeepSeek-V3 级别用 EP=32）
expert_tensor_parallel_size (ETP) 单个专家内部 专家内部张量并行；null（默认）= 与 TP 相同。建议与 TP 对齐

4.2 关键开关

参数默认说明
sequence_parallelTrueMegatron SP（LayerNorm/dropout 沿序列切分，配合 TP>1 使用），建议保持开启
use_distributed_optimizerTrue优化器状态沿 DP 分片（类 ZeRO-1），大模型必开
virtual_pipeline_model_parallel_sizenull虚拟流水线（interleaved 1F1B），降低 PP bubble，需配足够 micro-batch
use_megatron_fsdpFalseMegatron-FSDP（ZeRO-3 分片）路径
param_offload / optimizer_offloadFalse参数 / 优化器状态 CPU offload；param_offload 还会在 actor 空闲期释放梯度 buffer
override_transformer_config.recompute_*core_attn selective梯度检查点：recompute_granularity=full + recompute_method=uniform 最省显存，代价约 30% 重计算
use_remove_paddingTrueTHD 序列打包（去 padding），保持开启
PP 层数整除：transformer 层数必须能被 PP 整除，否则需用 override_transformer_config.num_layers_in_first/last_pipeline_stage、 account_for_embedding_in_pipeline_split 等手动指定切分。

5. Rollout 推理并行：vLLM / SGLang

rollout 是独立的推理引擎，有自己的并行参数（actor_rollout_ref.rollout.*）， 不必与训练后端一致。引擎共置时每个 rollout replica 占据 rollout TP × PP 张卡，replica 数 = world / (TP × PP)。

参数默认说明
rollout.tensor_model_parallel_size2推理 TP。卡数允许时尽量小（TP=1 最好），replica 多 = 吞吐高
rollout.data_parallel_size1显式声明 DP replica 划分（与 TP 一起决定切法）
rollout.expert_parallel_size1MoE 推理专家并行；vLLM 中 EP=1 表示 fused_moe 的 TP×DP 切分，EP>1（须满足 EP=TP×DP）才真正按专家切
rollout.pipeline_model_parallel_size1推理 PP，多数场景不用
rollout.gpu_memory_utilization0.5推理引擎可用显存比例（KV cache + 权重）。不开 offload 建议 0.5–0.7；训练侧 offload 全开后可到 0.8–0.9
rollout.max_num_seqs / max_num_batched_tokens256 / 8192并发请求上限 / 每 batch token 上限，决定解码期有效 batch；参考 max(8192, prompt+response, max_model_len)
rollout.enable_chunked_prefillTruechunked prefill 提升 GPU 利用率，需配合调大 max_num_batched_tokens
rollout.enforce_eagerFalseTrue 关 CUDA graph 省显存（CUDA graph 显存不受 gpu_memory_utilization 约束且无法 offload）
rollout.cudagraph_capture_sizesnull显存紧张时用小尺寸捕获，如 [1,2,4,8,16,32]，需 enforce_eager=False

5.1 KV cache 容量估算

选 rollout TP 时官方给出的经验判据（bf16/fp16 权重）：

单卡显存(bytes) × gpu_memory_utilization × rollout_TP > 2 × 参数个数

即 TP 张卡的总可用显存要装得下 bf16 权重（每参数 2 bytes）并留出同步余量，剩余部分全部做 KV cache。 在此基础上 TP 尽量小：HybridFlow 论文（arXiv:2409.19256）实验表明， 同样卡数下「多个小 TP replica」的 DP 吞吐通常优于「一个大 TP replica」，代价是总 KV cache 变多。

6. 各角色并行度对齐关系

  • ref（参考策略）：Megatron 路径下 TP/PP/CP/EP/ETP 应与 actor 完全一致（权重同步按相同切分传输）；offload 策略也建议对齐（actor 开 param_offload 则 ref 也开）。
  • critic：拥有独立的并行度配置，不必与 actor 相同；但 world_size 约束相同。critic 输出头小（标量 value），micro batch 可以比 actor 更大。
  • rollout：TP/EP 与训练侧无关，只需满足「权重同步能对上」——verl 会自动按 rollout 的 TP 切分广播 actor 权重。
  • reward model（如有）：与 critic 类似，独立配置。

7. 并行度 × 模型规模 × 序列长度的匹配

官方建议的调优顺序（best_practices.rst）：先加 TP → 放不下再加 PP → 长序列加 CP → MoE 对齐 EP/ETP 与 TP → DP 保持最小并配合 offload。以下为常见组合的经验起点（单卡 80G， 实际以显存监控为准）：

模型规模训练后端训练并行rollout TP备注
≤ 4B FSDP 全分片（fsdp_size=-1），DP=world 1 8 卡即可跑 PPO/GRPO；优先 DP
7B–8B FSDP 全分片或 fsdp_size=8（Hybrid Shard） 1–2 官方 GSM8K 基线：rollout TP=2、gpu_mem_util=0.6
14B FSDP / Megatron FSDP 全分片；或 Megatron TP=2 2 FSDP 下 logits（vocab 大）是显存瓶颈，用 dynamic bsz
32B 两者皆可 Megatron TP=4 PP=1；FSDP 需 param+optimizer offload 4 多机 FSDP 优先试 Hybrid Shard
70B Megatron TP=8（单机域），PP=节点数；use_distributed_optimizer=True 4–8 PP 跨机：通信只传边界激活；配 virtual pipeline 降 bubble
MoE（如 235B-A22B） Megatron TP=8 + EP=专家分片，ETP 对齐 TP；参考 DAPO+Qwen3-235B 最佳实践 TP=8 或 EP>1 MoE 显存大头是专家权重，EP 优先于 TP；DeepEP 跨机 EP 可提速
长序列 > 32k 两者皆可 FSDP: ulysses_sp=2–8；Megatron: CP=2–8 不受影响 同时把 *max_token_len_per_gpu 除以 SP/CP

7.1 显存快速估算（bf16 训练 + Adam）

参数   P 个参数：权重 2P bytes（÷ TP×PP，FSDP 下 ÷ fsdp 组）
梯度   2P bytes（同上分片）
优化器 fp32 master 权重 + m + v = 12P bytes
       → Megatron use_distributed_optimizer 或 FSDP 全分片后 ÷ DP
激活   ≈ micro_batch_tokens × hidden × layers × k（k 与是否开 checkpointing 强相关，
        开 full recompute 后每层只存输入，可降一个数量级）
logits ≈ tokens × vocab × (2~7) bytes  ← PPO 的额外大头，entropy/log-prob 计算峰值

例：70B 模型、bf16、Adam —— 静态部分 ≈ (2+2+12)×70G = 1120 GB，单机 8×80G=640G 放不下， 必须分片：TP=8×PP=2 后每卡 70GB 静态 + 激活，刚好达到上限，因此 70B 典型配置再加 offload 留余量。
